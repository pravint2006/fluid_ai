// Governance & Actions //

Authentication, Authorization & Business Actions

1. Authentication
  • Zero Plaintext Storage: Keys are digested with SHA-256 at startup; memory holds hashes only.
  • Constant-Time HMAC: Uses hmac.compare_digest to prevent timing side-channel attacks.
  • Zero Raw Key Logging: Audit entries record only a safe 8-character fingerprint (e.g. a6f632a6).
2. Authorization (RBAC)
  • Analyst User: Allowed to generate sales reports and submit support tickets. Blocked from employee directory.
  • Admin User: Full privileged access to all capabilities, including employee personnel records.
  • Strict 403 Forbidden: Unauthorized access attempts are rejected and logged as forbidden.
3. Business Actions
  • sales_report: Returns weekly sales revenue, orders, AOV, and AI summary.
  • create_ticket: Generates tracked support tickets in memory (e.g. TICK-0001).
  • employee_info: Corporate directory lookup (Admin only).
  • fallback: Natural guidance for unsupported prompts.
// Protection Systems //

AI Safety Workflow & Security Improvements

1. AI Safety Guardrail Workflow
  • ▸
    Dual-Tier Shield: Combines microsecond local regex filtering with cloud-based neural AI classification.
  • ▸
    Tier 1 Regex: Matches prompt injections (ignore previous instructions, reveal system prompt) and SQL injection syntax (union select, drop table).
  • ▸
    Tier 2 Meta Llama-Guard-4-12B: Evaluates prompt safety across 14 safety categories via NVIDIA NIM.
  • ▸
    Non-Blocking Threading: Offloaded via asyncio.to_thread so network latency never stalls the FastAPI event loop.
2. Key Security Improvements
  • ✔
    Secrets Decoupling: Removed all hardcoded credentials. All keys dynamically loaded from gitignored .env.
  • ✔
    Sliding-Window Rate Limiting: Thread-safe window enforcing 5 requests per 60 seconds per IP; rejects bursts with 429.
  • ✔
    Tamper-Evident Audit Logging: Structured JSON Lines logging with UTC timestamps, event codes, user roles, and client IPs.
  • ✔
    Zero Traceback Disclosure: Global exception handler catches unhandled exceptions, emits server_error, and returns generic 500.
// Incident Post-Mortem //

The Bug Story: Diagnosis & Resolution

1. Symptoms

When running run_tests.sh, Test 2.3 ("Lookup employee info for Alice") returned HTTP 400 Bad Request instead of the expected 403 Forbidden. Furthermore, even authenticated Admin users were completely blocked from looking up employee records!

2. Root Cause

Meta Llama Guard classifies employee lookups as unsafe\nS7 (Category S7: Privacy / PII). Because the guardrail ran before RBAC routing and treated any unsafe response as a prompt attack, it blanket-blocked the query before RBAC could authorize or restrict it.

3. How Diagnosed

We isolated the NVIDIA NIM API endpoint using standalone scripts to inspect the exact model response body: confirmed 'unsafe\nS7'. Traced audit.log which revealed premature injection_blocked events instead of forbidden.

4. How Resolved

Refactored verify_ai_guardrail to inspect category codes. When the sole flag is S7 (Privacy), the gateway delegates governance to the RBAC layer: Admins succeed with 200 OK, while Analysts are correctly denied with 403 Forbidden!

// Architectural Decision Analysis //

Tradeoff Discussion (1–2 Minute Deep Dive)

Tradeoff 1: Performance vs. Protection
  • The Dilemma: Neural safety models (Llama Guard NIM) provide deep semantic protection but add ~200ms network latency per query compared to sub-millisecond local regex.
  • The Concurrency Risk: Synchronous network calls in an async FastAPI route freeze the single-threaded event loop, stalling concurrent requests.
  • Our Decision: We implemented a hybrid approach: local regex stops known attacks in <1ms. For semantic evaluation, we offloaded the NIM call into a threadpool via asyncio.to_thread, and configured fail-open timeouts to safeguard availability.
Tradeoff 2: Security vs. Usability
  • The Dilemma: A zero-tolerance AI safety guardrail would blanket-ban all prompts mentioning employee names or directory lookups (Category S7 PII).
  • The Usability Impact: Legitimate business workflows (HR directory, staff lookup for admins) become completely unusable.
  • Our Decision: Instead of dropping the request at the firewall, we delegated Privacy (S7) governance to RBAC. Security enables the business: Admins get full usability; analysts remain strictly contained.
